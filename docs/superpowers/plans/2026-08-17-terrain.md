# Lutande terräng och suterränghus: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the plot a real ground shape, put the house in the slope with an exposed base storey, and show the result in the plan, in 3D, in a new side view and in the sun study.

**Architecture:** Height points and ground-levelling areas are baked into one height grid in `core/terrain`. Every renderer, the sun study and the side view read that one grid through a small query surface, so they cannot disagree. A document with no height information yields a null field, and every consumer short-circuits to flat ground at 0, which leaves existing projects unchanged in look and speed.

**Tech Stack:** SvelteKit 2, Svelte 5 runes, TypeScript strict, Canvas2D for plan and side view, three.js for 3D, earcut for triangulation, polygon-clipping for booleans, Vitest.

**Spec:** `docs/superpowers/specs/2026-08-17-terrain-design.md`

## How to work from this plan

This plan carries intent, not code. Design each step against the real source. Where it names a function and its parameters, that is a contract other tasks rely on, so keep the names. Where it describes a test, write the test that attacks the design rather than the one that confirms it.

## Global Constraints

- TypeScript strict. No `any`. No non-null `!` without a one-line reason.
- Metres throughout, `x` east and `y` north in core, mapped to three.js as `x` and `-z`. Radians in core, degrees only at the UI edge.
- `core` knows nothing about rendering or the DOM.
- Pure geometry and model code has tests. Rendering does not.
- No new dependencies. No barrel files, no `utils.ts`.
- Comments explain why, one line, only where the code cannot say it.
- Swedish UI copy, sentence case, no exclamation marks. Numbers in IBM Plex Mono.
- Heights display signed and two decimals: `+0.35`, `−1.80`.
- `npm run check`, `npm run lint` and `npm test` all pass before a task is done.
- User-facing tasks are not committed until Emmanuel has run the app and confirmed. Build the stage, say what to try, then hold.
- Commit messages: subject line only unless the diff leaves a real question. No apostrophes, no em dashes, no co-author trailer.

**Files:**
- Create: `src/lib/core/terrain/field.ts`
- Create: `src/lib/core/terrain/field.test.ts`

**Interfaces:**
- Consumes: `Doc`, `AreaEntity`, `docBounds` from `core/doc`, `Vec2` helpers.
- Produces:
  - `type HeightField = { x0: number; y0: number; cell: number; nx: number; ny: number; h: Float32Array }`
  - `buildField(doc: Doc): HeightField | null`
  - `heightAt(f: HeightField | null, x: number, y: number): number`
  - `type SpotSource = { at: Vec2; z: number }` if a seam for testing without a full `Doc` is wanted; keep it internal otherwise.

Task 4 adds the `spot` entity and the `grade` field. This task must not wait for it: build the field from whatever the document exposes by reading `e.k === 'spot'` and `e.grade` behind narrow local type guards, so Task 4 slots in without touching this file. Tests construct documents with those shapes directly.

- [ ] **Step 1: Write the failing tests**

Cover, one test each:
- An empty document returns `null`.
- One height point gives that height everywhere, including well outside the plot.
- Two points give a height that varies linearly along the line joining them and stays constant across it.
- Three non-collinear points give a plane: the field is exact at each point, and a fourth position on that plane reads its plane height to within a millimetre.
- Five points that are not planar: the field is still exact at every one of them.
- A graded area with `edge: 'wall'` is exactly its level everywhere inside, and unchanged one centimetre outside its ring.
- A graded area with `edge: 'bank'` and `run: 2` is its level inside, the ungraded height at 2 m out, and strictly between the two at 1 m out, with no overshoot past either end.
- Two overlapping graded areas: the later one in `doc.entities` wins in the overlap.
- Extent covers `docBounds` grown by 10 m.
- Cell count stays under 250 000 for a 400 m by 400 m document, with `cell` grown accordingly.

- [ ] **Step 2: Run the tests and watch them fail**

Run: `npx vitest run src/lib/core/terrain/field.test.ts`
Expected: every test fails, module not found.

- [ ] **Step 3: Implement the field**

Base surface: 0 points gives 0, one gives a constant, two gives linear along the joining line, three or more gives a least squares plane plus inverse distance weighted interpolation of each point's residual from that plane. The residual term must vanish for planar input, and reproduce each point exactly at its own position, so guard the zero-distance singularity. Then stamp graded areas in document order, later winning, using point-in-ring for the inside and distance to the ring for the bank band with a smoothstep blend.

`heightAt` is a bilinear lookup, clamped at the field edge, and returns 0 for a null field.

A graded ring can arrive self intersecting from a freehand draw, so clean it the same way the surface builders already do before stamping, and skip a ring that cleans down to fewer than three points.

- [ ] **Step 4: Run the tests and watch them pass**

Run: `npx vitest run src/lib/core/terrain/field.test.ts`

- [ ] **Step 5: Full gate and commit**

Run: `npm run check && npm run lint && npm test`
Commit: `Add the terrain height field`

### Task 3: Terrain queries

**Files:**
- Create: `src/lib/core/terrain/query.ts`
- Create: `src/lib/core/terrain/query.test.ts`

**Interfaces:**
- Consumes: `HeightField`, `heightAt`, `earcut`.
- Produces:
  - `groundUnder(f: HeightField | null, ring: readonly Vec2[]): { min: number; max: number }`, sampling the ring and its interior on the field grid, `{ min: 0, max: 0 }` for a null field.
  - `profileAlong(f: HeightField | null, spine: readonly Vec2[], step: number): { at: Vec2; z: number }[]`, resampled along the run at no more than `step` between samples, always including both ends and every vertex.
  - `drape(f: HeightField | null, ring: readonly Vec2[], holes: readonly Vec2[][], lift: number, maxEdge: number): { positions: Float32Array; index: Uint32Array }`, triangulated flat then subdivided until no edge exceeds `maxEdge`, then every vertex lifted to ground height plus `lift`. Output is in three.js axes so `render3d` can hand it straight to a `BufferGeometry`.

- [ ] **Step 1: Write the failing tests**

- `groundUnder` over a plane returns the true min and max of that plane over the ring, not just its vertex heights: use a ring whose interior contains the high point but whose vertices do not.
- `groundUnder` on a null field returns zeros.
- `profileAlong` never skips a vertex of the spine, and no consecutive samples are further apart than `step`.
- `drape` on flat ground with a large `maxEdge` produces the same triangle count as plain triangulation, all at `lift`.
- `drape` with `maxEdge` smaller than the ring produces more triangles, every vertex at its ground height plus `lift` to within a millimetre, and the summed triangle area in plan still equals the ring area.
- `drape` respects holes: no triangle centroid falls inside a hole.

- [ ] **Step 2: Run the tests and watch them fail**

- [ ] **Step 3: Implement the queries**

- [ ] **Step 4: Run the tests and watch them pass**

- [ ] **Step 5: Full gate and commit**

Run: `npm run check && npm run lint && npm test`
Commit: `Add terrain queries for ground, profile and drape`

**Interfaces:**
- Consumes: `HeightField`, `heightAt`, `groundUnder`, `profileAlong`, `drape`.

Details that matter:
- Flat document, null field: `buildGround` keeps exactly today's behaviour, one plane, and every other builder skips its terrain work. This is the regression guard for every existing project.
- Terrain mesh: the grid as triangles, with vertex normals, receiving shadow. Beyond the field extent it falls back to a skirt at the edge height so the world does not end in a cliff of nothing.
- Retaining faces: for every graded area with a hard edge, a vertical band from the level down or up to the surrounding ground, in the area's retaining material, built from the same cleaned ring the field stamped so the face and the ground cannot disagree.
- Areas and paths: draped, with `maxEdge` at the field cell size, keeping the existing `LAYER_LIFT` stacking. A graded area stays flat at its level.
- Plants: the instance matrix gains the ground height under the stem. No tilt, ever.
- Props: level, sitting at `groundUnder(footprint).max`.
- Fences and hedges: bottom and top follow `profileAlong`, posts upright and each post its own height, so the run rakes rather than floats.
- Plot tint: draped, not a flat ring.
